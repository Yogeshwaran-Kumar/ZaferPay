A

Algorithm: IsolationForest

The actual ML algorithm used

What it is: IsolationForest is an unsupervised anomaly detection algorithm from scikit-learn. It isolates anomalies by randomly selecting features and split values.

# From ai_scheduler.py, line 218 from sklearn.ensemble import IsolationForest challenger = IsolationForest( n_estimators=200, # 200 decision trees in the forest contamination=0.05, # Expect 5% of data to be anomalies max_features=0.8, # Use 80% of features per tree random_state=42, # Reproducible results n_jobs=-1 # Use all CPU cores )
Parameter Value What It Means
n_estimators 200 200 decision trees vote on whether a transaction is normal or anomaly
contamination 0.05 Assumes 5% of transactions in training data are anomalous
max_features 0.8 Each tree only sees 80% of the 28 features (randomization)

Why IsolationForest? It's designed for anomaly detection, doesn't require labeled fraud data, and is fast for real-time scoring.

Data Flow: Transaction → AI → Decision

Complete flow when scoring a transaction

1

Transaction Request Arrives

User wants to send ₹5,000 to another user. API receives: sender_id, receiver_id, amount, device_id, timestamp.

2

Feature Extraction

extract_features() runs 15+ database queries to calculate 28 features. Takes ~50-100ms.

3

Feature Array Creation

get_feature_array() converts the feature dictionary into a fixed-order array of 28 numbers.

4

Model Scoring

model.decision_function([features]) returns a float score. Negative = anomaly, Positive = normal.

5

Risk Score Adjustment

AI score converted to risk points: Strong anomaly → +65, Mild → +30, Very normal → -10.

6

Final Decision

Total risk score determines outcome: 0-30 → LOW (pass), 31-60 → MEDIUM (warn), 61+ → HIGH (block).

G

Guards: Model Security (HMAC Signing)

How the model file is protected

Problem: If an attacker replaces the model file, they could disable fraud detection.

Solution: Every model file is HMAC-SHA256 signed. On load, the signature is verified.

# HOW MODELS ARE SAVED (ai_scheduler.py line 70-79) def save_signed_model(model, path): model_bytes = pickle.dumps(model) # Serialize model # Create HMAC-SHA256 signature using secret key signature = hmac.new(HMAC_SECRET.encode(), model_bytes, hashlib.sha256) with open(path, "wb") as f: f.write(model_bytes) # Write model data f.write(signature.hexdigest().encode()) # Append 64-byte signature
# HOW MODELS ARE LOADED (fraud_engine.py line 590-628) def load_model_readonly(): with open(MODEL_PATH, "rb") as f: content = f.read() payload = content[:-64] # Everything except last 64 bytes embedded_sig = content[-64:] # Last 64 bytes = signature # Recalculate expected signature expected_sig = hmac.new(HMAC_SECRET.encode(), payload, hashlib.sha256).hexdigest().encode() if hmac.compare_digest(embedded_sig, expected_sig): _model = pickle.loads(payload) # ✅ Verified! Load model else: print("🚨 SECURITY ALERT: Model tampering detected!") # Model NOT loaded. AI disabled.

What happens in train_model()

1

Fetch Transaction History

Query last 10,000 successful transactions from database. Need minimum 30 to proceed.

2

Get Fraud Feedback

Query FraudEvent table for blocked transactions in last 30 days. These are labeled as "fraud" for training.

3

For each transaction, extract 28 features. Create pandas DataFrame.

4

Train Challenger Model

IsolationForest.fit(dataframe) - Trains new model on all data.

5

Champion-Challenger Test

Compare challenger vs current champion on last 100 transactions. Calculate correlation with known labels.

6

Promote Winner

If challenger beats champion by >5%, it becomes new champion. Otherwise, champion stays.

7

Save & Sign

Winner is serialized with pickle and HMAC-signed before saving to disk.

Rules-Only Mode (Fallback)

What happens if AI is unavailable

If the model file doesn't exist or signature fails, the system operates in "Rules Only" mode:

# From fraud_engine.py if not os.path.exists(MODEL_PATH): print("🛡️ Guard: No AI Model found. Operating in 'Rules Only' mode.") return # _model stays None # Later, when scoring: def get_ai_score(features): if _model is None: return 0.0 # Neutral score - AI has no opinion

In this mode, only the 54 rule-based checks run. The AI adds 0 points to risk score. This is a safe fallback.

⚠️ Known Limitation (Truth)

The AI learns from its own blocked transactions. If the rules block a transaction, it's labeled as "fraud" for training. This can create bias - the AI learns to agree with the rules rather than discover new fraud patterns. Ideally, human-verified labels would be used, but that requires manual review infrastructure.
