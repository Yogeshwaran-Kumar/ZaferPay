All Features (Actually Implemented)

Complete list of what the app can do

🔐 Security Features

🔑 Argon2id Password Hashing

Industry-leading password hashing algorithm. Same as used by Google. Resistant to GPU cracking attacks.

🔒 AES-256 Field Encryption

All sensitive data (balance, transaction amounts, messages) encrypted before database storage using Fernet (AES-256).

📝 HMAC-SHA256 Request Signing

Every API request includes a signature. Prevents man-in-the-middle modification of requests.

🔄 JWT + Refresh Token Rotation

Short-lived access tokens (15 min) with long-lived refresh tokens (7 days). Tokens rotate on refresh.

📱 Device Binding

Account locked to single device. Login from new device forces logout everywhere else.

⏱️ Rate Limiting

5 login attempts per minute. Prevents brute force password attacks using SlowAPI middleware.

🔐 Secure PIN Storage

PIN never stored on mobile device. All PIN verification happens server-side only.

📍 Geo-Velocity Check (F29)

Uses MaxMind GeoLite2 database to detect impossible travel. Blocks logins from impossible locations.

🕵️ Fraud Detection Features

📊 54 Rule-Based Detection

54 fraud patterns including velocity limits, circular loops, split transactions, night owl, and AML patterns.

🧠 28-Feature ML Engine

IsolationForest AI model with 28 behavioral features including geo-velocity and device trust scores.

🤝 Social Graph Trust Network

UserTrustGraph tracks relationships. Strangers face stricter limits than trusted contacts.

🏷️ MCC Tier System

5 merchant category tiers (Essential, High-Value, Retail, Services, Personal) with different rules.

📈 Auto AI Retraining

AI model automatically retrains every 24 hours using APScheduler. Champion-Challenger comparison.

💰 Daily Spending Limits

P2P: ₹1,00,000/day per receiver. Merchant: ₹3,00,000/day per receiver. Hard-coded safety.

💳 Payment Features

💸 UPI-Style Transfers

Send money via UPI ID, phone number, or QR code. Instant confirmation with transaction ID.

📷 QR Code Scanning

Scan UPI QR codes using camera with mobile_scanner package. Generate your own QR for receiving.

👥 Contact Integration

Import phone contacts. Check which contacts are registered SafePay users.

💬 Transaction Messages

Add notes/messages to transactions. Encrypted with AES-256 in database.

📜 Transaction History

Full history with sender/receiver names, amounts, timestamps, and status.

🔔 Risk Analysis Screen

Visual display of fraud analysis stages (Encrypting, Analyzing, Processing) before payment.

🙏 Payment Requests

Request money from other users (e.g., split bills). Track status (pending, paid, rejected).

🚨 User Fraud Reporting

Users can report suspicious transactions. Reports feed into the AI feedback loop for retraining.

📱 Mobile App Features

🏠 Home Dashboard

Shows balance, recent transactions, quick actions. Cached for instant loading.

👤 Profile Management

View account details, login history, trusted devices. Change PIN functionality.

🔄 Pull-to-Refresh

Refresh data on any screen by pulling down. Real-time balance updates.

💾 Offline Caching

SharedPreferences + FlutterSecureStorage for caching. Works with spotty connections.

🎨 Lottie Animations

Beautiful loading animations using Lottie for processing shield and fraud scanning.

📲 Root Detection

flutter_jailbreak_detection warns users on rooted/jailbroken devices.

End-to-End Workflow

Complete flow from user action to database

📱 User Login Flow

1

User Opens App

Flutter app loads. Checks FlutterSecureStorage for existing access token.

Flutter flutter_secure_storage
2

Enter Mobile Number

App sends POST /auth/check-mobile with device ID. Backend checks if user exists and device matches.

device_info_plus FastAPI
3

Enter PIN

User enters 4-6 digit PIN. App sends POST /token with mobile + PIN. Backend verifies PIN with Argon2id.

argon2-cffi python-jose
4

Token Issued

Backend generates JWT access token (15 min) + refresh token (7 days). Stores in secure storage.

JWT HS256 Keychain/KeyStore
5

Home Screen Loads

App calls GET /users/home. Backend decrypts balance from database, returns user data + recent transactions.

AES-256 Decrypt SQLAlchemy

💸 Payment Transaction Flow

1

User Initiates Payment

User selects receiver (UPI ID, phone, or QR scan). Enters amount and optional message. Taps "Pay".

mobile_scanner Flutter UI
2

Enter PIN for Authorization

PaymentPinScreen asks for PIN. PIN is NOT stored locally - will be sent to server for verification.

Server-side verification only
3

Processing Shield Animation

ProcessingShieldScreen shows 3-stage animation: Encrypting → Analyzing → Processing. Sends POST /transactions.

Lottie HMAC Request Signing
4

Backend: HMAC Verification

Backend verifies X-HMAC-Signature header. If mismatch, rejects request as tampered. Verifies PIN with Argon2id.

HMAC-SHA256 Argon2id
5

Backend: Fraud Engine Analysis

evaluate_fraud() runs 3-stage pipeline:
Stage 0: MCC Tier Classification
Stage 1: 54 Rule-Based Checks (velocity, patterns, AML)
Stage 2: Social Graph Trust Score
Stage 3: AI Anomaly Detection (26 features)

fraud_engine.py IsolationForest UserTrustGraph
6

Backend: Daily Limit Check

Checks F18 daily per-receiver limit (P2P: ₹1L, Merchant: ₹3L). Hard block if exceeded.

SQLAlchemy Query func.sum()
7

Backend: Balance Check & Lock

Uses pessimistic locking (FOR UPDATE) to prevent race conditions. Decrypts balance, checks sufficiency.

with_for_update() AES-256 Decrypt
8

Backend: Execute Transfer

Deduct from sender, add to receiver. Encrypt new balances. Create Transaction record with encrypted amount.

AES-256 Encrypt UUID Transaction ID
9

Backend: Update Trust Graph

record_trust() adds/updates trust relationship between sender and receiver. Increases trust score.

UserTrustGraph
10

Response to Mobile App

Backend returns success/failure with transaction details. App shows result screen with animation.

JSON Response Lottie Success/Fail

🤖 AI Auto-Training Flow (Background)

1

Server Starts

ai_scheduler.py starts APScheduler. Runs train_model() immediately on startup.

apscheduler BackgroundScheduler
2

Fetch Training Data

Loads last 10,000 successful transactions. Gets fraud feedback from FraudEvent table (blocked transactions).

SQLAlchemy FraudEvent model
3

Feature Extraction

Extracts 26 features for each transaction (amount, hour, velocity, trust score, etc.). Creates pandas DataFrame.

pandas numpy
4

Train Challenger Model

Trains new IsolationForest model with 200 estimators, 5% contamination rate.

scikit-learn IsolationForest
5

Champion-Challenger Comparison

Compares new model vs existing model on test data. New model must beat old by 5% to be promoted.

A/B Testing AUC Comparison
6

Sign & Save Model

Winner model serialized with pickle. HMAC-SHA256 signature appended. Saved as fraud_model_v2.pkl.

pickle HMAC Signing
7

Repeat Every 24 Hours

Scheduler triggers train_model() every 24 hours automatically. Continuous improvement.

IntervalTrigger(hours=24)
